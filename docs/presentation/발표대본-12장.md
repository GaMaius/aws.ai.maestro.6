## 2장. 작업자의 일 — 37초

1. 수입 화물 한 건에는 서류가 네 장 붙습니다.
2. 포워더의 작업자는 이 서류로 세 가지 일을 합니다.
3. 값이 서로 같은지 눈으로 확인하고, 품명과 수량을 손으로 옮겨 적고, 문제가 있으면 메일로 넘깁니다.
4. 세 번째가 어렵습니다. 서류를 고치는 것은 거래처이고 HS 코드를 정하는 것은 관세사라서, 작업자 권한 밖의 일입니다.

**조심**

근거: F1, `발표준비.md` 2번

## 3장. 놓치면 비용 — 24초

1. 이 두 서류는 같은 화물인데, 총중량의 앞 두 자리가 바뀌어 있습니다.
2. 눈으로 보다가 이런 한 칸을 놓치면, 정정과 검사로 통관이 늦어집니다.
3. 관세청은 오류 신고의 74퍼센트가 품목분류 오류라고 밝혔습니다.

**조심**
- **'출처 확인 필요' 표시가 붙은 숫자(7.5억 원, 6만 원, 100만 원, 10%)는 출처가 올 때까지 말하지 않는다.**
- 74퍼센트는 '오류 신고 가운데 품목분류의 비중'이다. '신고의 74퍼센트가 오류'가 아니다.
- "한국 통관 서류의 몇 퍼센트가 틀린다"고 말하지 않는다.

근거: 근거표 3절, D003 정답지

## 4장. 해결 — 36초

1. 그래서 세 가지 일을 이렇게 바꿨습니다.
2. 눈으로 확인하던 일은, 코드가 규칙으로 대조합니다.
3. 손으로 정리하던 일은, AI가 서류를 읽고 코드가 신고서 초안을 채웁니다.
4. 메일로 넘기던 일은, 근거 문서를 붙여 자동으로 보냅니다.
5. 읽기는 AI, 판정은 코드, 예외만 사람입니다. 3분 영상으로 보시겠습니다.

**조심**
- "나머지는 전부 Agent가 한다"고 말하지 않는다. HS 확정과 승인은 사람이 한다.
- "AI가 HS를 결정한다", "세관 신고까지 자동"이라고 말하지 않는다. 후보 추천과 초안까지다.
- 자연어 조회(기능 ⑤)는 이 구성에서 말하지 않는다. 물으면 질의응답 Q12로 답한다.

근거: 근거표 2절, A2, F9, F15

## 5장. 서비스 화면 — 24초

1. 영상에서 보신 작업 화면입니다.
2. Agent가 도구를 골라 서류를 나누고 읽습니다.
3. 세 장 가운데 상업송장만 값이 달라서, 코드가 상업송장을 짚었습니다.
4. 그 칸은 읽을 때와 다른 방법인 Textract로 한 번 더 확인했습니다.

**조심**
- "에이전트가 판정한다"고 말하지 않는다. 에이전트는 도구와 순서를 고르고 판정은 코드가 한다.
- 캡처에 통지 문서 버튼이 '준비 중'으로 보이면 #276이 배포된 뒤 다시 찍는다.

근거: A8, A9, D4, E4

## 6장. 자동 메일 — 30초

1. 불일치나 정해지지 않은 HS가 남으면, 관리자에게 메일이 갑니다.
2. 불일치 통지 문서와 HS 확인 요청서가 PDF로 붙습니다.
3. 관리자는 확인한 뒤 거래처와 관세사에게 전달하면 됩니다.
4. 메일도 문서도 코드가 만듭니다. 모델이 쓰지 않습니다.

**조심**
- "거래처와 관세사에게 자동으로 보낸다"고 말하지 않는다. 메일은 관리자에게 한 통 가고, 전달은 사람이 한다.
- 배포본에서 메일을 켰는지는 PM 확인을 기다리는 중이다(#270 댓글). 꺼져 있으면 "보낼 수 있게 만들었다"로 말한다.

근거: F13, F15, F8

## 7장. 믿을 수 있는 이유 — 57초

1. 이 결과를 믿을 수 있는 이유입니다.
2. 주최 측 샘플 서류가 없어서, 코드보다 서류 479장과 정답지를 먼저 만들었습니다.
3. 그 정답지로 모델 혼자와 비교했습니다. 심은 오류 37건은 둘 다 모두 찾았습니다.
4. 실제 판독으로 75세트를 끝까지 돌렸을 때도 37건을 모두 찾았고, 오탐은 없었습니다.
5. 모델 혼자와의 차이는 작았습니다. 그래도 판정은 코드에 맡겼습니다.
6. 같은 서류에는 같은 판정이 나와야 하고, 근거가 코드에서 나오고, 이 판정이 등록을 막고 푸는 스위치이기 때문입니다.

**조심**
- "실제 서류로 검증했다"고 말하지 않는다. 합성 서류이고 양식은 8가지다. 발표용 세트는 열지 않았다.
- 표의 37건과 0세트는 정답 값을 넣어 규칙만 잰 값이다. 75세트는 고정 순서로 한 번 잰 값이고, "오탐은 없었다"는 오류를 하나도 심지 않은 30세트 기준이다.
- "모델에 맡기면 흔들린다", "코드가 더 정확하다", "모델은 근거를 못 낸다"고 말하지 않는다.
- 40번은 4세트를 10번씩 고정 순서로 잰 값이다. 에이전트 루프를 켠 조건으로는 다시 재지 않았다.

근거: A3~A8, A11, A16, A17, B1, B2, B6, B7, B10

## 8장. 왜 이 순서인가 — 56초

1. 읽기는 비전 모델입니다. 양식마다 규칙을 짜지 않아도 되고, 품목 줄까지 읽습니다.
2. 판정은 코드 규칙입니다. 같은 서류에 같은 판정이 나오고, 짚은 칸과 근거가 남습니다.
3. 다시 확인은 어긋난 칸만 합니다. 읽을 때와 다른 방법, 곧 PDF 글자나 Textract 글자로 합니다.
4. 순서를 바꿔서도 재 봤습니다.
5. Textract로 먼저 읽으면, 좌표 규칙을 짜야 72칸 중 71칸이 나옵니다. 그런데 그 규칙은 저희 양식 전용입니다.
6. 모델에게 판정까지 맡기면, 오류 없는 4세트를 불일치로 봤습니다.

**조심**
- "비전 모델이 OCR보다 정확하다"고 말하지 않는다. 표본이 다르다(Textract 47장 72칸, 비전 모델 150장 450칸).
- "처음 보는 양식도 잘 읽는다"고 단정하지 않는다. 양식 8가지로만 쟀다.
- Textract 측정은 4번이 한 것이다. 규칙 없이 묻는 방식은 63칸이었다.

근거: A3, A6, A12, A14, D1, D2, D3

## 9장. 자동은 근거가 둘일 때만 — 39초

1. 자동의 기준은 하나입니다. 근거가 둘일 때만입니다.
2. HS 코드는 AI가 추천만 하고, 확정은 사람이 합니다.
3. 같은 수입자의 같은 품목은 다음부터 이력으로 자동 확정됩니다.
4. WMS 등록도 같습니다. 문제가 없고 HS가 모두 정해진 건만 자동으로 등록합니다.
5. 나머지는 다음 할 일 한 줄과 함께 사람에게 갑니다.

**조심**
- "AI가 HS를 확정한다"고 말하지 않는다.
- "자동 확정 70건 중 틀린 것 0"은 정답 값 채점이고, 사람 선택을 정답으로 넣은 가정이다.
- 등록은 '가상 WMS'다. 물으면 그렇게 답한다.

근거: F2, F3, F5, F6, F10, F11, F14

## 10장. 아키텍처 — 30초

1. 배포는 서버리스입니다. 서류가 올라올 때만 일하므로 늘 켜 둘 서버가 없습니다.
2. Lambda는 둘로 나눴습니다.
3. API Gateway는 30초 안에 답해야 하는데, 한 세트 처리가 30초 안팎입니다.
4. 그래서 API Lambda는 바로 답하고, 처리 Lambda가 뒤에서 돕니다.

**조심**
- "모두 서울에서 처리한다"고 말하지 않는다. 모델 추론은 global 프로필이다(11장).
- "실시간"이라고 말하지 않는다. 대시보드는 1분마다 새로 고친다.

근거: `TEAM.md` 배포 구조, `infra/config.sh`, E4

## 11장. 모델: 리전과 비용 — 41초

1. 통관 서류에는 거래처와 금액이 있어서, 어디서 처리되는지를 따져 봤습니다.
2. 지금 모델은 Sonnet 5.5이고, global 프로필이라 추론이 국외에서 처리될 수 있습니다.
3. 서울에서 직접 부를 수 있는 Sonnet 5로 같은 정답지 15장을 다시 쟀습니다. 분류와 읽기 결과가 같았습니다.
4. 비용은 서류 네 장 한 세트를 끝까지 처리하는 데 약 0.18달러입니다.

**조심**
- "Sonnet 5를 쓴다"고 말하지 않는다. 지금 배포는 Sonnet 5.5(global)이고 PM이 유지하기로 정했다(#224).
- "환경 변수만 바꾸면 된다"고 말하지 않는다. 환경 변수, 권한 정책, 배포 스크립트 세 곳이다.
- 0.18달러는 75세트를 고정 순서로 돌린 평균이고 토큰 실측 × 직접 요금 어림이다. 배포본은 에이전트 루프라 호출이 더 든다.

근거: G1~G4, G8~G10

3. 정리하면, 눈으로 확인하던 일은 코드가, 손으로 정리하던 일은 AI와 코드가, 메일로 넘기던 일은 근거와 함께 자동으로 합니다.
