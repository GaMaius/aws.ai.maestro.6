# 데이터셋 규칙과 심는 오류

`samples/generate_dataset.py` 가 데이터를 만들 때 지키는 규칙(G)과, 포장명세서에 일부러 심는 오류(E)다.
관세 규칙 담당이 규칙표 v1과 `rule_id` 를 정할 때 이 문서와 맞춘다. 숫자는 기본값(시드 6) 기준이다.

## 구성

| 항목 | 값 |
|---|---|
| 세트 | 125개. 개발용 `D001`~`D075`, 발표용 `T001`~`T050`. 세트 하나 = 상업송장 1장 + 포장명세서 1장. 개발용과 발표용은 난수와 번호대를 따로 써서, 개발용을 바꿔도 발표용은 그대로다 |
| 오류 | 세트의 60%에 하나씩 (개발용 45건, 발표용 30건). 세 칸(수량·총중량·송장 번호)에 고르게 |
| 정상 세트 | 개발용 30, 발표용 20 |
| 거래처 | 수출자 10 (중국 5, 베트남 5), 수입자 5 (부산·경남). 모두 가상이고 이름에 SAMPLE·EXAMPLE |
| 품목 | 24개. 정답 HS 10자리는 관세청 HS부호 표(2026-01-01 기준)에서 확인 |
| 양식 | 스타일 1(KOTRA 수출 가이드북 86·87쪽 칸 구성)과 스타일 2(Shipping Solutions 양식) 반반 |
| 파일 | PDF 60%, PNG 40%(150dpi). 상업송장이 doc_a인 세트와 포장명세서가 doc_a인 세트가 반반 |

## 생성 규칙 (G)

| 번호 | 규칙 | 데이터에 들어간 모습 | 근거 |
|---|---|---|---|
| G1 | 부산항 수입 | 도착항은 모두 `BUSAN, KOREA`, 수입자는 부산·경남 | 과제 원문 |
| G2 | 정답 HS는 실제 한국 10자리(HSK) | 카탈로그의 HS가 HS 표에 있고 송장 기간(2026-09-01~11-12)에 유효해야 생성된다. 아니면 생성기가 멈춘다 | 관세청 HS부호 |
| G3 | 송장 단위와 HS 수량단위가 맞음 | PCS↔U(개), PRS↔2U(켤레), M2↔M2. 중량으로만 신고하는 HS(볼트, 새우, 커피 등)는 PCS나 KGS | HS부호 표 수량단위코드 |
| G4 | 인코텀즈 지정 장소 | FOB=선적항, CFR·CIF=도착항(BUSAN), EXW=수출자 도시. 비율 FOB 55 · CIF 20 · CFR 15 · EXW 10 | Incoterms 2020 |
| G5 | 선적항은 수출자 위치에 맞음 | 수출자마다 항구 하나(상하이, 선전, 닝보, 칭다오, 광저우, 호찌민, 하이퐁). 항차 끝 글자는 중국 출발 E, 베트남 출발 N | |
| G6 | 날짜 순서 | 송장일 2026-09-01~11-12, 선적일 = 송장일 + 2~9일 | |
| G7 | 포장·중량 계산 | 박스 = 올림(수량 ÷ 박스당 수량), 순중량 = 수량 × 단위 순중량, 총중량 = 순중량 + 박스 × 박스 무게, CBM = 박스 × 박스 부피. 20%는 마지막 박스가 덜 참. 카탈로그 숫자는 반올림하지 않고 그대로 쓴다 | 양식의 계산 시트 |
| G8 | 송장의 HS 표기 | **스타일 2 상업송장만** HS 칸이 있고, 품목마다 6자리(`7318.15`), 한국 10자리(`8467.21-0000`), 표기 없음 중 하나. 스타일 1 상업송장과 포장명세서에는 HS 칸이 없다. 정답 HS는 정답지에만 있다 | agent-design.md (외국 송장에는 한국 10자리가 드묾) |
| G9 | 문서 번호 | 송장 번호는 수출자별 형식, 주문 번호는 수입자별 형식. 날짜 순서대로 커지고 겹치지 않음. 번호대가 달라(개발용 100번대~, 발표용 1100번대~) 두 분할이 겹치지 않음 | |
| G10 | 원산지 | 수출국과 같음 (`MADE IN CHINA`, `MADE IN VIETNAM`) | |
| G11 | 한 세트 안 품목 | 같은 수출자, 같은 단위, 같이 실을 수 있는 것만 (냉동 새우와 캐슈너트는 따로) | |
| G12 | 수입자 | 식품은 식품 수입자(KR04), 생활용품은 주로 KR05, 그 밖은 KR01~KR03 | |

## 심는 오류 (E)

포장명세서의 한 칸만 바꾸고, 상업송장은 원래 값이다. 정답지의 `doc` 은 `packing_list`, 원래 값은 `original_value`.
모든 차이는 허용 오차(중량 0.1kg)보다 크다. 총중량 오류는 한 줄의 총중량을 바꿔서 합계가 따라 바뀐다.
송장 번호 오류는 끝 세 자리 안에서만 바꾸고, 데이터에 이미 있는 번호(다른 세트의 진짜 번호)가 되지 않게 한다.
아래 예는 개발용에서만 뽑았다(발표용 값은 이 문서에도 적지 않는다).

| 번호 | 칸 (`field`) | 방식 (`error_type`) | 실제 예 | 임시 `rule_id` |
|---|---|---|---|---|
| E1 | `total_qty` | `digit_swap`: 붙은 두 숫자 자리 바뀜 | D006 2행 수량 589 → 598 | X-QTY-01 |
| E2 | `total_qty` | `zero_slip`: 0 하나 더함·빠짐 | D015 수량 2050 → 205 | X-QTY-01 |
| E3 | `total_qty` | `carton_slip`: 한 박스만큼 많음·적음 | D020 수량 1640 → 1620 | X-QTY-01 |
| E4 | `total_gross_kg` | `decimal_shift`: 소수점 한 자리 밀림 | D002 총중량 556.5 → 55.65 | X-WT-01 |
| E5 | `total_gross_kg` | `digit_swap` | D007 총중량 3621.75 → 3261.75 | X-WT-01 |
| E6 | `total_gross_kg` | `net_as_gross`: 순중량을 총중량 칸에 씀 | D008 총중량 658 → 611 | X-WT-01 |
| E7 | `total_gross_kg` | `lb_as_kg`: 파운드 값을 kg 칸에 씀 | D010 총중량 736 → 1622.6 | X-WT-01 |
| E8 | `invoice_no` | `char_swap`: 끝 번호 두 자리 바뀜 | D003 SHE-2026-0323 → SHE-2026-0332 | X-INV-01 |
| E9 | `invoice_no` | `digit_typo`: 끝 번호 한 자리 오타 | D004 MKS-260111 → MKS-260151 | X-INV-01 |

## 발표용 세트 잠금

- 발표용 입력(`data/sets_test.csv`)과 정답지(`eval/test/`), 서류(`test/`)는 git에 올리지 않는다.
  Kiro나 Claude Code가 저장소를 읽다가 발표용 정답을 보고 프롬프트를 맞추는 일을 막기 위해서다.
- 생성기는 발표용이 이미 있으면 다시 만들지 않는다(`--force-test` 를 줘야 만든다).
- 확인이 끝나면 `check_samples.py --lock-test` 로 잠근다. 해시만 적은 `samples/test_lock.json` 을 커밋하고 태그를 단다.
  그 뒤로 발표용 파일이 하나라도 바뀌면 `check_samples.py` 가 잡는다. 잠금 뒤에는 생성기와 `build_samples.py --test` 가 발표용을 다시 만들지 않는다.

`rule_id` 는 `build_samples.py` 의 `RULES` 에 있다. 규칙표 v1이 나오면 거기만 바꾸고 서류를 다시 만든다.

## 채점할 때 알아둘 점

- **스타일 2 상업송장은 품목이 여러 줄이면 총수량을 찍지 않는다.** 정답지(`eval/fields.csv`)의 상업송장 `total_qty` 는 줄 수량의 합이다.
  읽기 결과도 `docs/schema.md` 약속 1처럼 줄마다 읽고, 합계는 코드가 더해서 비교한다.
- **날짜 모양이 양식마다 다르다.** 스타일 1은 `SEP. 08, 2026`, 스타일 2는 `10/07/2026`(월/일/년). 일/월로 읽으면 틀린다.
- **송장에 찍힌 HS는 정답이 아닐 수 있다.** 6자리이거나 비어 있을 수 있다(G8). 정답은 `eval/sets.csv` 의 `hs_answer`. 포장명세서에는 HS가 없다.
- **PNG는 OCR 확인이 완벽하지 않다.** `check_samples.py` 는 표 테두리 때문에 OCR 두 가지 모드를 합쳐 읽는다. 그래도 값을 못 찾으면 '눈으로 확인'으로만 표시한다.
- **품명은 그림으로 확인한다.** 칸 밖으로 잘린 글자도 PDF 글자층에는 남아 있어서, `check_samples.py --docs` 는 서류를 그림으로 그려 품명의 처음과 끝이 보이는지 본다. `build_samples.py` 는 품명 줄 수에 맞춰 행 높이를 늘리고, 서류가 한 장을 넘으면 멈춘다.

## 아직 넣지 않은 것 (2단계)

- **B/L (P1):** 컨테이너 번호 체크 디지트(ISO 6346), 선적일보다 입항일이 늦은지, B/L 총중량·포장 수와 포장명세서 대조
- **원산지증명서 (P1):** 한-중 FTA, 한-아세안·한-베트남 FTA 증명서 양식, 원산지와 HS 6자리 대조
- **서류 한 장 안 합계 오류 (P1):** 수량 × 단가 ≠ 금액, 줄 합 ≠ 총계 (양식에 `CI_total_amount_ovr`, `PL_total_gross_ovr` 칸이 있다)
- **HS 오류 (P1):** 송장 HS가 정답과 다름 (X-HS-01)
- **수입요건 (P2):** 세관장확인대상(예: 전기용품 KC 인증, 식품 검역). 관세 규칙 담당 조사 뒤
- **휴대폰 촬영본:** 현장에 프린터가 있으면 발표·영상 담당이 출력해서 찍는다
